# CFP committee rankings predictor

The CFP tab is separate from AP voting and Henderson power rankings. Daily publishing runs `python football-model/export_cfp.py --refresh` after the main game model. It publishes completed-result rankings, a deterministic favorites-win scenario through the next official release, the dated official archive, and prior-season-only backtests. ESPN logos use CFBD team IDs.

Training uses 72 CFP releases from 2014–2025. Run `OPENBLAS_NUM_THREADS=1 python football-model/train_cfp.py` to retrain after adding a complete season. Walk-forward evaluation covers 41 releases in 2019–2025; each fold rebuilds training pairs using strictly earlier seasons. Fixed ridge strength is 800; the baseline is the inherited committee-protocol weights. Validation is historical reconstruction, not archived live forecast performance.

Inputs are game-derived resumes: wins/losses, record and schedule strength, opponent quality, quality wins, bad losses, conference championships and opponent-adjusted ratings. Comparable teams receive head-to-head/common-opponent adjustments. No AP targets, target CFP ranks, roster data, or future game results enter the historical input builder. Target records are used only to validate reconstructed records. Duplicate game IDs are deduplicated. Results require a four-hour buffer; release cutoffs are noon UTC, including Selection Sunday. Margins enter the underlying strength rating. Quality wins use model-rated opponents.

Rank error is uncapped full-rank error for actual ranked teams; it is not directly comparable to the AP tab's rank-26 cap. Top 12 overlap measures rankings, not playoff selection or seeding. The current early-season outlook has less information than the November/December releases used for backtesting.

`polls.json` is the curated dated history, checked against reconstructed game records. The official week-by-week archive has several legacy duplicate-rank typos, so refresh imports only current-year releases and preserves existing polls and strictly validates 25 distinct ranks/teams for new releases. Source format changes fail publishing rather than create partial rankings. Official future schedules must be added to `schedule.json` annually; the exporter also rejects a model not trained through the preceding season. Review the official archive URL annually. Existing pre-release forecasts are retained when their target poll arrives and labeled separately from reconstructions.
